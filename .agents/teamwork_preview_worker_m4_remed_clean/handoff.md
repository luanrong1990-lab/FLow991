## 1. Observation

### Observation 1.1: Invalid FFmpeg Video Filter `copy` in `build_filter_graph`
- **Location**: `services/ffmpeg_service.py`, lines 343–350:
  ```python
  if vf:
      filter_complex_parts.append(f"[0:v]{vf}[v_out]")
  else:
      filter_complex_parts.append("[0:v]copy[v_out]")
  ```
- **Finding**: In FFmpeg filtergraphs, `copy` is NOT a recognized video filter; it is an output stream codec flag (`-c:v copy`). Supplying `[0:v]copy[v_out]` into `-filter_complex` triggers a fatal error from FFmpeg:
  ```
  [AVFilterGraph @ ...] No such filter: 'copy'
  Error initializing complex filters.
  ```
  The correct pass-through filter in an FFmpeg filtergraph is `null` (e.g., `[0:v]null[v_out]`).

### Observation 1.2: Silent AI Video Clips Crashing BGM Mixing
- **Location**: `services/ffmpeg_service.py`, line 350 & line 378 (originally lines 325 & 353):
  ```python
  filter_complex_parts.append(f"[0:a]volume={voice_volume}[voice]")
  ```
  and:
  ```python
  complex_parts.append(f"[0:a]{audio_filter}[a_out]")
  ```
- **Finding**: AI video clips generated by Veo 3.1 Lite on Google Flow are often silent (containing no audio track). When input 0 lacks an audio stream, referencing `[0:a]` causes FFmpeg to exit fatally with:
  ```
  Stream specifier ':a' in filtergraph description [0:a]volume=1.0[voice] matches no streams.
  ```
  FFmpeg supports optional audio stream specifiers via `[0:a?]`. Furthermore, when input clips are known to be silent, bypassing the `[0:a]` voice ducking/amix stage and connecting `[1:a]` (the BGM track) directly to `[a_out]` provides a clean, robust render.

### Observation 1.3: Adversarial and Unit Test Alignment
- **Location**: `tests/test_ffmpeg_adversarial.py` lines 120–152 and `tests/test_ffmpeg_engine.py`.
- **Finding**:
  - `tests/test_ffmpeg_adversarial.py` explicitly tests for defect 1 in `test_bgm_enabled_without_upscale_defect_detection`:
